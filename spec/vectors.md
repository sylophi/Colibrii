# Test vectors

Every SDK must reproduce these exactly. They live as JSON files under
`spec/vectors/`, one per subject, generated by the TypeScript SDK and
checked in. A vector never changes once released: a change to the wire
adds new vectors under the new version.

Each file is a list of cases. A case has a `name`, its `inputs`, and the
`expected` outputs, with binary values in base64url unless a field's
name says otherwise (`hex`). In `hub.json`, `inputs` names what the case
is, and `expected` holds the message or body as `json` (or as `text`,
for `ping` and `pong`), with the `status` beside it for an error. A
case in `hub.json` or `link-transport.json` that is what a later
version may send ([README.md](README.md), "Growing the wire") holds it
in `inputs`, as `json`, as it arrives, and `expected` holds what a
reader ends up with. The handshake
vectors fix every key, ephemeral keys included, so the bytes are
deterministic. Noise libraries allow fixing the ephemeral key for tests,
and an SDK's vector tests must use that and nothing else. Every payload
a vector seals is given as its exact bytes, since the ciphertext depends
on them.

## Subjects

| File | What it pins down |
|---|---|
| `base64url.json` | Encoding and decoding, with and without padding on input. |
| `noise.json` | `Noise_IK_25519_ChaChaPoly_SHA256` with fixed keys and a prologue: both handshake messages, the handshake hash, and transport messages in both directions. |
| `relay.json` | Whole `ask` and `answer` frames for given device ids, keys and payloads, and the ask and answer as the reader reads them. |
| `link-handshake.json` | The link's first message for a given ticket and keys, and the listener's answer. |
| `link-transport.json` | The plaintext and ciphertext of `hello`, `welcome`, `refuse`, `ping`, `pong`, and an app message split into pieces, and a `hello`, a `welcome` and a `refuse` with a field the reader does not know. |
| `hub.json` | Every hub socket message, and the HTTP request and answer bodies, as JSON. |
| `tunnel-label.json` | The label for given app, account and device ids. |
| `credential-hash.json` | The stored SHA-256 of a device credential. |

`hub.json` and the HTTP bodies are compared as parsed JSON. The
service's own tests check them too, so the service and every SDK read
the same samples. `tunnel-label.json` and `credential-hash.json` are for
the service alone: a device never computes either.
